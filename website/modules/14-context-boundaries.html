📚 Core Concepts

Observe: a partner's data arrives

A made-up partner, the Tradeline Directory, offers a feed of business listings. Each listing looks like this:

FieldExampleWhat it means to Tradeline
listing_idTL-0042Tradeline's own ID
trading_nameSaltwater Kitchen Pty LtdThe legal trading name, with suffix
sector_codeHSPTradeline's three-letter sector code

None of these match the Company Enricher's words. Tradeline says listing, we say company. Tradeline has sector codes, we have categories. Its names include "Pty Ltd", which our website lookup does not expect.

The tempting shortcut is to pass the listing dictionary straight into the core and add if listing["sector_code"] == "HSP" wherever needed. Within a month, Tradeline's codes would be scattered through the policy, the tests, and the reports, and a change on their side would break code everywhere.

Say it plainly: translate once, at the border

Stage 04 adds one module, adapters/partner_directory.py, with one job: turn a Tradeline listing into our Company.

  • listing_id becomes our company_id, prefixed tradeline: so it cannot clash with IDs from elsewhere.
  • trading_name loses its legal suffix and becomes name.
  • sector_code is mapped through a table to one of our Category values, which becomes the company's directory_hint.
  • A code we have no mapping for becomes "no hint", never a guess.

After the translation, the core sees only Company and Category. The partner's vocabulary stops at the adapter, and Day 13's SuggestionPolicy can use the hint in our own terms: if the directory and the website disagree, the company needs review for conflicting sources.

A simple context map shows who speaks which language:

ContextIts languageRelationship to the Company Enricher
Company Enricher (ours)company, category, suggestion, needs reviewthe core
Company websitesURLs, HTML, About pagesoutside; reached through the website adapter
Tradeline Directorylisting, trading name, sector codepartner; translated by the anticorruption layer
Review teamthe same language as oursdownstream: works from our results

Name it: bounded context, context map, anticorruption layer

Eric Evans's Domain-Driven Design, Chapter 14, "Maintaining Model Integrity", explains that a model is only consistent within a boundary. A bounded context is the explicit boundary within which one model and its language apply. A context map shows the bounded contexts in play and how they relate. An anticorruption layer is an isolating layer that translates between your model and another system's, so the other model cannot corrupt yours.

The translation table is a model decision, not plumbing. Mapping ICT to Software & IT is a claim the reviewers should agree with, which is why it lives in one readable place.

Evans's free DDD Reference describes an anticorruption layer as an isolating layer that gives your code the other system's functionality in terms of your own model, and talks to the other system through the interface it already has. That is company_from_listing: Tradeline keeps its feed, and we keep our words.

💡
Key Insight: Every external model you let in unchanged becomes part of your model. Translate it at the border, in one place.

Example 2: The anticorruption layer

stage 04 · enricher/adapters/partner_directory.py
def company_from_listing(listing):
    """Translate one Tradeline listing into a Company.

    Unknown sector codes become "no hint", never a guessed category.
    """
    name = listing["trading_name"]
    for suffix in LEGAL_SUFFIXES:
        name = name.removesuffix(suffix)
    return Company(
        company_id=f"tradeline:{listing['listing_id']}",
        name=name,
        directory_hint=SECTOR_CODE_TO_CATEGORY.get(listing.get("sector_code")),
    )

What's happening: input in Tradeline's words, output in ours. Nothing after this function knows Tradeline exists.

Example 3: Testing the translation

stage 04 · tests/test_partner_directory.py
def test_unknown_sector_code_gives_no_hint():
    listing = {"listing_id": "TL-0099", "trading_name": "Quiet Hours Studio", "sector_code": "ZZZ"}
    assert company_from_listing(listing).directory_hint is None

What's happening: the safest translation of an unknown value is "we don't know", which the policy treats as no hint.

Exercise 2 · Change: the partner changes its feed (⏱️ ~15 min)

Goal: See the anticorruption layer absorb a change.

Instructions:

  1. Tradeline renames trading_name to business_name and adds a new code AGR for agriculture.
  2. Update company_from_listing so it accepts the new field name.
  3. Decide what AGR should map to, given our category list, and write down why.
  4. Add a test for each change, then run python -m pytest -q and confirm no file outside adapters/ changed.
Hint

We have no Agriculture category, so AGR maps to no hint until the business adds one. Day 4 showed that adding a category is one edit.

Optional exercise: swap in a real taxonomy (e.g. ANZSIC or NAICS) behind an adapter, so the core keeps its own plain category list. Write a second translation table from a published industry classification to our Category values, and test it the same way.

Exercise 3 · Transfer: draw a context map (⏱️ ~10 min)

For a system you know, list every outside system it exchanges data with. For each, write two of its words that differ from yours, and where the translation happens today.
