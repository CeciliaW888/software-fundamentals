# Mission: Software Fundamentals

## Why
Build the software judgment needed to understand, design, review, and evolve reliable systems rather than merely assembling working demos.
Use one evolving Python service so each fundamental becomes part of a real system.

## Success looks like
- Read unfamiliar Python code and explain its data flow, contracts, failure modes, and trade-offs.
- Design and review a production service with clear boundaries, tests, observability, and deployment discipline.
- Refactor generated or inherited code into code a team can safely change.
- Ship improvements in small, testable increments.

## Constraints
- Lessons should be short enough to complete in one focused session.
- Every lesson must produce one tangible improvement to the evolving project.
- Prefer retrieval practice and immediate feedback over passive summaries.
- Ground teaching in high-trust primary sources.

## Out of scope
- Memorising framework APIs that can be looked up.
- Building a new course platform before the lessons prove useful.
- Chasing every new tool, framework, or headline.
