Meaningful names for Python AI systems

Make the data stage, unit, decision, and domain visible before a reader opens a comment or debugger.

One-page testCan a reviewer predict the value and its unit from the name alone?

The naming stack

SignalQuestionExamples
Domain nounWhat real thing is this?document, retrieval_query, model_response
StageWhere is it in the pipeline?raw_documents, validated_chunks, ranked_results
UnitWhat does the number measure?timeout_seconds, cost_usd, token_count
Decision verbWhat outcome does the function choose?select_relevant_chunks, reject_unsafe_output
BoundaryWhich system owns the value?openai_response, database_record, api_request

Fast review

  • Replace generic verbs such as run, handle, and process with the decision or transformation.
  • Put units in numeric names when confusion is plausible.
  • Distinguish raw, validated, embedded, retrieved, ranked, and generated data.
  • Use one word for one concept across the service.
  • Rename when understanding improves. Names are maintained design.

Smell → repair

SmellRepair
scorecosine_similarity or classification_confidence
limitmax_results, token_limit, or timeout_seconds
dataName the domain object and pipeline stage.
process_response()Name the observable transformation or decision.
A comment translating a short nameMove that meaning into the name.
A good name is a tiny contract: it narrows what a value can mean before tests or types speak.
