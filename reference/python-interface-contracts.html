Field reference

Python interface contracts

Record every fact a caller must know and hide every implementation detail it can safely ignore.

Body-free testCan a caller use this function correctly without reading its implementation?

The contract stack

PartQuestionTypical evidence
PurposeWhat outcome does the callable provide?Name and summary sentence
InputsWhat values and constraints are accepted?Parameters, types, ranges, required states
ReturnWhat does each possible result mean?Return type, sentinel values, edge cases
Side effectsWhat observable state can change?Writes, messages, mutations, resource ownership
FailuresWhat can the caller observe when work fails?Exceptions, error values, partial completion
PreconditionsWhat must already be true before the call?Ordering, lifecycle, permissions, invariants

Keep out of the interface

  • Private helper names and call order
  • Current algorithm or data structure
  • Retry count unless it changes a public guarantee
  • Database or vendor choice behind an abstraction
  • Line-by-line narration of obvious code

Contract-test filter

AskKeep the assertion when…
Could implementation B honour the same promise?The assertion still passes after a valid rewrite.
Can a caller observe this?The result, state, failure, timing guarantee, or interaction crosses the boundary.
Would changing this break a legitimate caller?The change requires coordination or a versioned contract.
Strong contracts are complete about behaviour and silent about replaceable machinery.
